Undervalued NBA Players

An end-to-end basketball analytics pipeline that predicts team wins, attributes impact to players, builds a custom wins-above-replacement metric and surfaces player-seasons that beat model expectations.

Project Overview

From team outcomes to player value

The project turns historical team and player data into a reproducible modeling workflow. Alongside a previous-season team wins forecast, it distributes team-level performance to players and measures each player against a replacement baseline. A final expectation model asks which player-seasons produced more value than their playing time, prior performance and career context suggested.

Data & Reproducibility

Built to be rerun and audited

  • Source: Sumitro Datta's NBA, ABA, BAA Stats dataset on Kaggle.
  • Inputs: Team Summaries, Player Totals, Advanced and All-Star Selections.
  • Stack: Python 3.10+, pandas, scikit-learn, NumPy, Matplotlib, joblib and KaggleHub.
  • Scope: player-season rankings from 1991 through the completed 2025–26 season, with both all-player and non-All-Star variants.
  • Guardrail: the 2026 build stops unless all 30 NBA teams have 82 regular-season games, preventing partial-season data from being labeled final.
  • Artifacts: model metrics, player contributions, cWAR tables, validation reports, current-season impact rankings, charts and shareable visuals.

Column Definitions
  • Season: Season end year (for example, 2026 = 2025-26 season).
  • Player: Player name.
  • Team: Team abbreviation for that season.
  • Games: Games played.
  • Minutes per Game: Minutes per game (mp / g).
  • cWAR: This project's custom wins-above-replacement estimate.
  • Prev cWAR: Prior season cWAR (0 if unavailable).
  • Prev Minutes: Prior season minutes played (0 if unavailable).
  • Prev Games: Prior season games played (0 if unavailable).
  • Career Season #: Career season number in dataset (1 = first season).
  • Expected cWAR: Model-expected cWAR.
  • Value Residual: Observed cWAR minus model-expected cWAR.
  • Undervalued Score (WAR): Value residual adjusted by the square root of minutes per 1,000.
  • Season Residual Z: Within-season z-score of value residual.

Methodology

Open Methodology

A) Previous-Season Team Wins Predictor

  1. Discover the team-season source table containing the wins target.
  2. Shift available team inputs back one season within each franchise so future results do not leak into the predictors.
  3. Use the oldest 80% of observations for training and the newest 20% for chronological evaluation.
  4. Fit a preprocessing and random-forest pipeline, then save the model and its MAE, RMSE and R² metrics.

B) Player Wins Contribution

  1. Build player feature table from Player Totals.csv + Advanced.csv.
  2. Compute minute share inside each team-season:
    mp_share = player_mp / team_total_mp
  3. Build team-level weighted features:
    contrib_feature = mp_share * player_feature
  4. Train a Ridge model to predict team wins (w) from weighted team features using a chronological 80/20 split.
  5. Convert team prediction back to players:
    raw_pred_contribution = sum(contrib_feature * model_coef)
    Scale to team actual wins context using scale_to_actual.
  6. Apply stabilization:
    actual_scaled_contribution_raw = raw_pred_contribution * scale_to_actual
    shrink_factor = g / (g + 35)
    actual_scaled_contribution = actual_scaled_contribution_raw * shrink_factor
    Clip actual_scaled_contribution to ± (0.30 * g).
  7. Compute above-average value:
    season_league_avg_contribution = mean(actual_scaled_contribution by season+lg)
    wins_above_average = actual_scaled_contribution - season_league_avg_contribution
    Clip wins_above_average to ± (0.22 * g)
    wins_above_average_per_1000_mp = (wins_above_average / mp) * 1000

C) Salary-Free Undervalued Model

  1. Aggregate to one row per player-season.
  2. Train Ridge model to predict expected value from usage/history with features: mp, g, mp_per_game, prev_wins_above_average, prev_mp, prev_g, career_season_num, season_idx.
  3. Compute residual value:
    expected_wins_above_average = model prediction
    value_residual = wins_above_average - expected_wins_above_average
  4. Compute final ranking score:
    undervalued_score = value_residual * sqrt(mp / 1000)

D) Custom cWAR Table

This WAR is built from project metrics, not Basketball-Reference ows/dws.

  1. Start from player_win_contributions.csv.
  2. Aggregate to one row per player-season-league.
  3. Compute impact rate:
    wins_above_average_per_1000_mp = (wins_above_average / mp) * 1000
  4. Estimate replacement level per season+league:
    rep_waa_per_1000_mp = 20th percentile of wins_above_average_per_1000_mp (default, mp >= 250)
  5. Compute rate above replacement:
    rate_above_replacement = wins_above_average_per_1000_mp - rep_waa_per_1000_mp
  6. Convert to wins and apply durability:
    cwar_raw = rate_above_replacement * (mp / 1000)
    durability_factor = g / (g + 20) (default)
    cwar = cwar_raw * durability_factor
    cwar_rank is rank within each season + lg.

E) cWAR-Based Undervalued Model

  1. Use nba_war_player_seasons.csv as the input feature table.
  2. Train Ridge model to estimate expected custom WAR (expected_cwar) using: mp, g, mp_per_game, prev_cwar, prev_mp, prev_g, career_season_num, season_idx.
  3. Compute residual value:
    value_residual = cwar - expected_cwar
  4. Compute final WAR-based market score:
    undervalued_score_war = value_residual * sqrt(mp / 1000)

Validation & Interpretation

Useful signal, with explicit boundaries

The repository tests team cWAR against team wins on a chronological holdout, prior-year team cWAR against next-season wins, player cWAR against Win Shares, BPM, VORP and WS/48, and year-to-year player stability. These checks evaluate association and predictive usefulness; they do not prove that cWAR isolates causal player impact.

  • Project-specific metric: cWAR is not Basketball-Reference WAR, Win Shares, VORP, RAPTOR, EPM or an official NBA statistic.
  • Model meaning: “undervalued” means outperforming the model's expectation, not necessarily being underpaid.
  • Data limits: box-score inputs cannot fully capture lineup, matchup, coaching or possession-level effects.
  • Use: the results are research and educational analysis, not official player evaluations or personnel advice.
